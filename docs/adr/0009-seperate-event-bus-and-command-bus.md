# ADR-0009: Separate Event Bus and Command Bus

**Status:** Accepted

## Context

OpenExtraction is a distributed embedded control system.

The Controller receives information from multiple independent sources, including:

- ESP-NOW messages
- Embedded web interface
- Physical buttons
- Timers
- Internal watchdogs
- Future communication transports

Likewise, the Controller communicates with multiple outputs:

- Machine Nodes
- Gate Nodes
- Dust Collector relay
- Event logger
- Future external systems

Early designs treated events and commands as a single concept.

During architectural review it became apparent that events and commands represent fundamentally different concepts.

An event represents something that has already happened.

A command represents a request for something to happen.

Mixing these concepts would blur responsibility between business logic and transport layers.

## Decision

The Controller SHALL implement two independent internal communication buses:

- Event Bus
- Command Bus

The Event Bus SHALL transport immutable facts.

The Command Bus SHALL transport requests generated by Controller logic.

Business logic SHALL communicate exclusively through these buses.

Subsystems SHALL NOT directly invoke one another.

## Event Bus

The Event Bus transports facts.

Events SHALL:

- be immutable
- represent completed occurrences
- contain no behavioural intent
- be publishable to multiple consumers

Examples include:

- MachineDemandStarted
- MachineDemandStopped
- GateOpened
- GateClosed
- GateFault
- CollectorStarted
- CollectorStopped
- DeviceOffline
- ConfigurationChanged

## Command Bus

The Command Bus transports requests.

Commands SHALL:

- express desired behaviour
- originate from Controller logic
- target a single recipient
- never directly modify Controller state

Examples include:

- OpenGate
- CloseGate
- StartCollector
- StopCollector
- PairDevice
- RebootDevice

## Responsibilities

Transport adapters SHALL translate external communication into Events.

Transport adapters SHALL translate Commands into protocol-specific messages.

Business logic SHALL remain independent of transport implementation.

Business logic SHALL NOT directly access:

- ESP-NOW
- HTTP
- GPIO
- persistent storage

## State Changes

Controller state SHALL only change while processing Events.

Commands SHALL NOT directly modify Controller state.

Completion of Commands SHALL be confirmed by subsequent Events.

## Consequences

Advantages:

- Clear separation between facts and requests.
- Transport-independent business logic.
- Deterministic behaviour.
- Easier unit testing.
- Easier simulation.
- Simpler addition of new transports.
- Reduced coupling between subsystems.

Disadvantages:

- Additional architectural components.
- Event dispatcher and command dispatcher are required.

These disadvantages are considered acceptable because they significantly improve maintainability and extensibility.

## Example

```
                    ESP-NOW

                       │

             Message Decoder

                       │

                       ▼

          MachineDemandStarted

                  (Event)

                       │

                Event Dispatcher

                       │

                Routing Engine

                       │

                 OpenGate

                 (Command)

                       │

              Command Dispatcher

                       │

             ESP-NOW Encoder

                       │

                 Gate Node
```

No subsystem may bypass the Event Bus or Command Bus.

All communication SHALL pass through the appropriate bus.
